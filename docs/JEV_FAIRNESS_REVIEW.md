# Jev 实验的公平性复核

复核日期：2026-11-01。范围：历史 `9e107fe` 精排报告、当前 `experiments/nli4ct_study.py` 和评分调用实现。此次未调用付费模型，未读取 NLI4CT 测试答案或根据测试成绩调参，也未修改运行中的实验。

**复核区分三个问题：旧任务无法充分区分模型、实现给时延增加了不对称开销，以及质量比较本身是否失效。** 前两项确实存在；没有发现能把已发表质量数字整体推翻的证据。现有结论应保持为“在这些任务和这套策略下，尚未证明 Jev 优于强简单基线”，不能写成“Jev 没用”。

## 旧实验实际回答了什么

| 实验 | 合理的结论 | 不能据此推出 |
|---|---|---|
| 基础 planner 已经 50/50 的四分支 gate | 该 gate 配置增加了错误阻拦和过度澄清；不适合直接部署 | Jev 不能发现错误计划，或所有决策模型都没有价值 |
| 8 道显式 NCT ID 的证据题 | Jev、Luna 和范围规则均优于未筛选的 hybrid 顺序；固定池中只够完整回答 6 题 | Jev 的语义排序能力等同于一个 ID 规则，或混合检索普遍无效 |
| 单个事后补查案例 | 模型能根据缺口发起检索，并恢复所需证据 | 改善由 Jev 单独造成，或此策略有普遍收益 |

四分支 gate 的任务复合、错误计划阳性样本不足，确实不适合代表决策模型的全部价值；不过它仍是“给现有系统加这道 gate 是否有益”的有效负结果。后来增加的 ID 规则直接使用用户问题中的 ID，没有读取标准答案，是应该保留的强对照，不是对 Jev 不公平。

单段相关性 Noul 本身也不是明显错误用法。TypeSafe 官方重排示例就是先检索候选，再对每个 query–candidate 问一个相同的问题并排序；官方还明确区分相关性、答案证据、矛盾和提示注入等不同判断。[TypeSafe 重排示例](https://docs.typesafe.ai/cookbooks/rerank_typesafe)、[片段分类示例](https://docs.typesafe.ai/cookbooks/classifying_rag_passages)。Haystack 的 TypeSafeRanker 同样采用逐文档评分，并提供并发参数。[Haystack 文档](https://docs.haystack.deepset.ai/docs/typesaferanker)。因此不能因为当前只问一项相关性，就认定“没有正确使用 Jev”；更复杂的多项策略应成为单独的实验组。

## 已确认的公平性和解释边界

1. **候选池存在上限。** 旧实验的两题缺少必要候选，所有精排器都无从补回。应分别报告初召回覆盖、池内排序质量和最终上下文覆盖；不要把缺候选记为 Jev 单独失败，也不要从达到池内上限推断无法再优化系统。
2. **旧题明显偏向结构化范围规则。** 显式 ID 加上很少的必要片段，给了范围规则很强的优势。这是产品中真实且值得优化的任务，但不是广泛语义精排能力的代表。新实验需包含同试验内相似措辞、否定条件、不同试验角色、数值条件和多句组合证据。
3. **存在具体的连接复用差异。** `model_score` 每次 Jev 调用都新建并关闭 `httpx.Client`，而 Luna 复用传入的 OpenAI client。因此历史 34.14 秒与16.32秒包括不同的连接管理成本；不能称为模型固有延迟。后续[独立时延对照](JEV_LATENCY_CONTROL.md) 已在相同客户端生命周期和并发设置下测量，并在该小样本开发集探针中观察到 Jev 更快；它没有复现旧任务的全部运行条件，不能量化解释旧时差的全部来源，也不改变质量比较结论。
4. **当前比较的是完整评分系统，不是纯模型能力。** MiniLM 用原始声明；Jev/Luna 获得相关性任务说明。它们拥有不同训练目标和接口，合理比较应允许各自使用预先确定的适配方式，但需给各组相同的开发/校准机会。仅一个英文 MS MARCO MiniLM 不能代表所有专用 reranker。
5. **相关性与证据集合充分性不同。** 独立逐句评分不直接优化去重、多句共同推理或覆盖两侧试验。这个局限同时影响 Jev、Luna 和单句 cross-encoder。下一步可比较共享的邻句窗口或章节上下文，再独立测试增量价值选择，不能只给某一组额外上下文。
6. **精确引用、完整上下文和正确答案应分开。** 当前 NLI 主答案指标是标签正确率；`citation_ids_valid` 只说明引用 ID 来自输入，不能证明它支持结论。报告还应单列回答引用的必要证据覆盖和无依据引用比例。不可把上下文包含所有证据写成“回答完整正确”。

## 当前 NLI4CT 协议的输入审计

仅检查官方 test 的无标签输入及 tokenizer，未读取 gold 或正式结果：

| 项目 | 观察 |
|---|---:|
| 问题数 | 500 |
| 全部来源 query–sentence 对 | 10,836 |
| MiniLM 超过512 tokens的对 | 0 |
| MiniLM 最长输入对 | 340 tokens |
| 全文序列化上下文不超过1024 tokens | 237/500 |
| 来源句子数不超过24 | 326/500 |
| 中位句子数 / 全文 tokens | 16 / 1,108 |
| 最长全文上下文 | 8,130 tokens |

全部500条声明都提到 primary 或 secondary；候选中保留的 `role` 对区分试验有用。没有证据表明这轮 MiniLM 被512-token截断限制，不能拿它解释未来的输赢。

接近一半题目的全文原本就可能放进预算，因此它们主要检验阅读和推理，精排差异会被稀释。建议**在看成绩之前**固定按预算是否触发、候选池是否截断、Single/Comparison 和章节分层报告，仍保留完整500题作为主分母。

已保存[逐题输入分层](public-evaluation/nli-input-strata.json)：237题同时满足全文≤1024 tokens和来源≤24句；229题为Single、271题为Comparison；章节分别为Intervention 142、Eligibility 132、Results 106、Adverse Events 120。共享来源试验的题目形成113个关联分量，可用于补充的分组不确定性分析。这份分层在正式执行启动后、此复核者读取任何测试标签或评分结果之前登记；不声称在运行启动前预注册。237题的候选与预算均不受限，排序仍可能影响答案顺序效应，但证据集合覆盖没有同等的改善空间。

当前复用了资格标准实验的 `RELEVANCE` 文案，其中“requested criterion / another criterion”对 Results、Adverse Events 可能不够贴切。这是需要开发集验证的假设，不是已证实的失败原因。当前正式运行可以作为该固定策略的测量保留，不应在看到测试结果后修改提示词、预算或抽样名单。

## 后续公平对照的具体安排

- **先把范围对齐。** 显式 ID 任务从初召回开始限定范围；同一来源池下比较 BM25、dense、RRF。把“换了候选池”与“换了精排器”的收益分别报告。
- **相同开发预算。** 在 train/dev 比较当前相关性 rubric 与通用“支持或反驳此声明的证据”rubric；Jev/Luna 使用相同字段、相同候选和相同上下文单位。提前固定一次选择，之后锁定测试。
- **保留五组主对照。** Hybrid、专用 reranker、Jev、便宜通用模型、全文。另加 BM25 直接装配的廉价对照。全文不受选择预算限制，需明确其成本和信息量不同，它是读取全量来源的基准。
- **单独做机制消融。** 句子 vs 邻句窗口、固定top-k vs开发集阈值、纯相关性 vs增量覆盖策略。不要把同时改召回、上下文和停止规则的收益归到 Jev 本身。
- **另测可部署时延。** 两个远程接口都复用持久客户端，固定相同最大并发，cold/warm分开，交换或随机化组别顺序，报告p50/p95、失败率和总输入token。保存每次调用费用，包括未采用和失败尝试。旧时延保留为旧实现的实际观测。
- **报告不确定性。** 给逐题配对差异、置信区间与任务分层。NLI 多题可能共享试验，区间至少附一个按试验关联分组的敏感性分析；不要把500题等同于500个完全独立临床场景。

## 正式报告器的独立复核

在正式研究仍执行时，仅复核冻结源码、协议和输入分层元数据，未读取部分成绩或现场费用账本。复核确认：四个选择器的候选集合、装配上限一致；MiniLM 也读取候选 JSON 元数据，并非仅看到段落正文。Jev/Luna 的相关性 rubric 相同，但与 MiniLM 的适配方式不同，因此应解释为预定系统对照。

已在报告层补充两类检查，不改执行器或原始成绩：一是验证实际候选集合、token 上限和引用 ID 集合标记，添加 Jev–Luna / Jev–MiniLM 的直接配对区间；二是修正“相同内容账本即同一次运行”的不安全推断，只对同一物理文件别名去重，独立文件即使字节相同也保留并标记。后者避免两个仅包含相同未知调用预留的独立失败运行被误合并，不表示当前正式费用已经发生这种错误。

报告另外区分空引用列表、非空且合法的引用 ID、上下文必要证据覆盖和标签正确率。合法 ID 并不证明语义支持；1024 个序列化上下文 token 也不等于整个链路具有相同输入量或成本。正式组别费用按显式调用标签计入，未知/共享开销单列；本地 CPU 没有换算为美元。完整命令和输入依赖见[公开评测文档](PUBLIC_EVALUATION.md#protocols-and-complete-reporting)。这些分析项在未读取正式结果时登记，保留全部主分母和原有历史实验，不用于调整 Jev 提示词或选择有利子集。
